# LlamaDock 動画スタック 全体フロー（2026-08-17）

機能が増えて全体像が見えにくくなったので、**「何が・いつ・どこで動く/止まる」**だけを整理したメモ。
コードの細部は各ファイル（select-model.ps1 / tools/h3-chat.ps1 / tools/h3-chat.py）を参照。

## 1. 常駐 3 サービスの役割

| ポート | サービス | 役割 | 推論 |
|---|---|---|---|
| **8188** | ComfyUI | 動画生成・キー画像生成の実行エンジン | GPU（VRAM 全部使う） |
| **8189** | h3-chat（Python） | ブラウザで開くチャット UI。ComfyUI へのプロキシ | CPU |
| **8190** | 企画 LLM（llama-server + Qwen3.5） | 日本語企画会話・キー画像の視覚認識・英語プロンプト作成 | **CPU（-ngl 0）** |

企画 LLM が CPU 推論なのは **VRAM を ComfyUI に全部残すため**（RX 7800 XT 16GB 前提）。

## 2. 動画スタックで使うモデル（4 系統）

| 系統 | モデル | いつ動く | どこで切る |
|---|---|---|---|
| 企画 LLM | Qwen3.5-4B Uncensored Q8（4.4GB）+ mmproj 視覚（675MB） | 企画モードの会話・画像認識・プロンプト作成 | 自動停止 or セッション [4] |
| キー画像 | Z-Image NSFW GGUF Q8（7.2GB） | 企画モードでキー画像生成（15〜35 秒） | 動画生成直前にアンロード（VRAM 解放） |
| 動画 DiT | PinkCherry int8（21GB）/ **10Eros NVFP4（12.5GB）** | 動画生成時（数分） | 自動停止 or [4] |
| 動画付属 | turbo LoRA / 参照 LoRA（R2V）・テキストエンコーダ（4B fp8 / 32B NVFP4） | 動画生成時に DiT に重ねる | DiT と一緒 |

## 3. 起動シーケンス（いつ誰がオンになるか）

```
llamadock（select-model.ps1）
 └ [7] plan を選択
     ├─ ComfyUI を起動（ck チューニング付き）→ 8188
     └─ h3-chat.ps1 を呼ぶ
          ├─ 企画 LLM（llama-server）を起動 → 8190（Qwen3.5 + mmproj・CPU）
          └─ h3-chat を起動 → 8189
     準備ができたらブラウザで 8189 を自動オープン
```

- **h3-chat.py 単体起動**でも、8190 が落ちていれば**自動で llama-server を起動**する（起動時バックグラウンド + リクエスト時再接続）。
- 二重起動ガード: 8189 と 8190 が両方生きてれば何も起動せずブラウザを開くだけ。llama-server も再利用。

## 4. 生成フロー（企画モード・フル）

```
① 日本語でアイデアを打つ
     ↓ h3-chat(8189) → 企画LLM(8190)
② 企画 LLM が日本語で打ち返して具体化（何度でも）
     ↓
③ キー画像プロンプト確定 → Z-Image がキー画像を生成（GPU・15〜35秒）
     ↓
④ 画像を確認 → 必要なら修正指示（企画 LLM が再考）
     ↓
⑤ 確定 → Z-Image をアンロード（VRAM 解放）
     → 企画 LLM がキー画像を【視覚で見て】英語の動画プロンプトを作成
     ↓
⑥ 動画生成（ComfyUI: H3 DiT + turbo LoRA [+ 参照 LoRA]）quick ≈4分 / high ≈9分
     ↓
⑦ 完成 → 自動停止カウントダウン
```

- **🔗 参照モード（R2V）**にチェックすると、確定キー画像を `<Picture 1>` 参照にして
  同一キャラ維持の動画になる（H3 DiT + 参照 LoRA、ref2va モデル不要）。VRAM は +0.2GB のみ。
- **企画モードなし**でそのまま送信すると、①〜⑤を飛ばしてテキストのみで ⑥ へ直行。

## 5. 停止シーケンス（どこで切るか）

| 経路 | 動き |
|---|---|
| **自動（推奨）** | 動画完成 → ブラウザに 90 秒カウントダウン（🛑今すぐ終了 / ComfyUI だけ / キャンセル）。放置しても **サーバー側 180 秒で確実に**: `POST /free`（モデルアンロード→VRAM 解放）→ ComfyUI kill → 企画 LLM kill → h3-chat 自己終了。ブラウザを閉じていても動く |
| **手動** | セッションメニュー `[4] Stop server and exit` → 「動画スタックも停止して GPU+RAM を解放するか？」に `y` → Stop-H3Stack が 8188/8189/8190 をコマンドライン照合で kill |
| **部分** | 自動停止のカウントダウンで「ComfyUI だけ」→ 8188 のみ停止、チャットは残る |

## 6. VRAM 配分（16GB 前提）

```
企画 LLM ─── CPU 推論 → VRAM 使わない
キー画像 ─── Z-Image ≈7GB → 動画の前にアンロード
動画 ─────── H3 DiT ≈13.3GB（10Eros は NVFP4 エミュレーション）+ R2V なら +0.2GB
```
→ キー画像と動画は**同時に載せない**設計（h3-chat が生成前に `_free_comfy()` でアンロード）。

## 7. 関連する別系統（動画スタックではない）

- **web-ui/**（ポート 3000・Node 依存ゼロ）: llama.cpp のパラメータ GUI・起動/計測/ベンチ・ワークスペース接続。動画スタックとは独立。
- **mcp-server.js**: Serper Web 検索（MCP 経由・キャッシュ付き）。
- ポート 8090: リカバリゲートウェイ（LLM ハーネス側）。
